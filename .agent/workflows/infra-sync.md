# Infrastructure Sync Workflow (`/infra-sync`)

## Context
This workflow is invoked when an agent detects infrastructure drift during story development or bug fixing (e.g., via `infrastructure-sync-guardian`). It ensures that local or ad-hoc infrastructure changes are synced back to the Single Source of Truth (`2.5. architecture.md`) and that downstream epics and stories are updated.

## Execution Steps

<steps CRITICAL="TRUE">
1. PIVOT & UPDATE ARCHITECTURE (TDR-Compliant, Zero-Trust):
   - Read the physical evidence of infrastructure drift (usually generated by `infrastructure-sync-guardian` at `_iwish-output/adhoc-workspace/scratch/infra-drift-evidence.json`).
   - If the file is missing, HALT immediately and ask the user to provide the evidence manually.
   - Use the evidence to update the Global Infrastructure Map and relevant ADRs in `_iwish-output/2. Product Planning/2.5. architecture.md`.
   - **[CHANGE LOG — APPEND ONLY]**: When updating ANY ADR/TDR section, you MUST append a new row to the `#### Change Log` table with: ISO 8601 date, change description, reason for the change, and a file link to the drift evidence (`[evidence](file:///path/to/infra-drift-evidence.json)`). You MUST NOT overwrite existing Change Log entries.
   - **[SCALE-PHASE TRANSITION]**: If the drift evidence indicates a phase transition (e.g., tenant count crossing 100 or 1000, latency exceeding threshold), update the `#### Scale-Phase Roadmap` to mark the current active phase and record the actual metric value that triggered the transition.
   - **[ZERO-TRUST & SSOT SYNC]**: After updating `architecture.md`, you MUST trigger a rebuild of the Technical Decision Registry (TDR) by instructing the user to run `/reconcile-change` or by executing `python3 .agent/scripts/extract-tdr.py` (if available) to update `tech-decision-registry.yaml`. The new staleness check will cause failures if `architecture.md` is newer than the TDR. Finally, run `python3 .agent/scripts/validate-tdr-format.py <path> --evidence-output _iwish-output/adhoc-workspace/scratch/tdr_validation_post_sync.json`. If TDR Compliance Score < 70% → HALT.

2. IMPACT ANALYSIS:
   - Run the cross-epic drift detector script targeting architectural drift:
     ```bash
     python3 .agent/scripts/detect-story-drift.py --architecture
     ```
   - Analyze the output to identify all Epics and Stories that rely on the outdated infrastructure patterns.

3. PLAN COVER GAP (DEBT SCHEDULING):
   - For every affected Epic and Story identified in Step 2, generate technical debt tickets or refactoring tasks.
   - Write these tasks to the refactoring queue directory: `_iwish-output/runtime/refactoring-queue/` using the format `refactor-story-{story_id}.yaml`.
   - Ensure each refactoring task explicitly references the architectural changes made in Step 1.

4. USER REVIEW & ALIGNMENT:
   - Present a summary of the updated infrastructure map and the scheduled refactoring tasks to the user.
   - Request user confirmation before ending the workflow.

5. NAVIGATOR GUARDIAN SYNC (CRITICAL):
   - Upon completing the workflow, you MUST explicitly run `bash .agent/scripts/navigator-guardian.sh` via the terminal to synchronize the Idea Navigator dashboard.
</steps>
