# Edge Case Guardian Loop

The Edge Case Guardian Loop is a Zero-Trust, self-healing pipeline. It enforces a strict feedback loop between the Review Agent (finding edge cases) and the Dev/Architect Agent (mitigating them) until physical evidence proves all risks are resolved, culminating in an Out-of-Band Cryptographic Seal.

## Trigger Mechanisms

### 1. Automated Integration (Pipeline Triggers)
This loop is automatically triggered at the end of the following standard workflows to guarantee zero-trust compliance before advancing:
- **Story Creation (`/make-story`)**: Ensures ACs are robust.
- **Spec Generation (`/make-ui-spec`, `/make-data-spec`)**: Scans for state machine flaws and concurrency risks.
- **Implementation Planning**: Whenever an `implementation_plan.md` is generated before `/code`.
- **Epic Evaluation (`/evaluate-epic`)**: Scans the *Actionable Implementation Plan* generated by the evaluation report (which handles new ACs or gap-filling stories, not code).
- **Macro Architecture Updates (ADR, TDR, AE)**: Triggers whenever macro-level design documents are updated to prevent systemic architectural regressions.
- **Retrospectives (`/iwish-feature-retrospective`)**: Used to validate root cause analysis and preventative measures.

### 2. Manual Invocation (Standalone Trigger)
When the user explicitly invokes `/edge-case-guardian` on a specific file or plan, the system does NOT just run a single scan. 
**Manual invocation explicitly triggers the continuous LOOP until approval is achieved.**

## Pipeline Execution

The Orchestrator agent coordinates the loop. The final verdict and cryptographic signing MUST be executed by the Watchmen MCP:
```bash
# Example MCP Call via agent:
call_mcp_tool(ServerName="watchmen-mcp", ToolName="sign_pipeline_gate", Arguments={"artifact_path": "<path_to_artifact>", "gate_name": "<gate_name>"})
```

### 🔄 Anti-Premature Delegation & Autonomous Loop Rule
**MANDATORY:** The Orchestrator MUST NEVER stop to ask the user for permission to update or remediate a `BLOCKED` artifact during the Edge Case loop. It must autonomously loop up to 25 times.
- **Exception for Structural Failures:** The only time the Orchestrator may ask the user for permission is if the circuit breaker trips (25 iterations reached) or if there is a severe infrastructure failure (e.g., API limits, missing MCP server). If 25 iterations are reached without `PROVEN_SAFE`, notify the user and propose continuing the loop or running `/party-mode` to find a solution.

### Phase 1: Guardian Scan (Orchestrator-driven)
- The Orchestrator spawns the Review Agent (loaded with the Edge Case Guardian skill).
- The Review Agent parses the target artifact and outputs the FMEA analysis and status (`PROVEN_SAFE` or `BLOCKED`).

### Phase 2: Remediation Loop (Orchestrator-driven)
- If `BLOCKED`, the Orchestrator MUST autonomously spawn a Dev Agent (or fix it directly) to remediate the artifact.
- **Context Pruning Mandate (EC-P11-001):** When looping, the Orchestrator must ensure the conversation context does not bloat. Rely on physical files for history rather than long chat threads.
- **Circuit Breaker:** 25 iterations max.

### Phase 3: Out-of-Band Verification (Watchmen MCP)
- If `PROVEN_SAFE`, the Orchestrator MUST call `watchmen-mcp:sign_pipeline_gate`.
- The Watchmen MCP will generate a detached `.sig` file next to the artifact.
- **Seal Persistence Instruction (EC-P5-001):** If the artifact is rolled back or modified later, the `.sig` file MUST be deleted immediately to prevent signature mismatch vulnerabilities.

## Resilience & Recovery
- **Physical Rollback Mechanism (EC-P2-002, EC-P4-001):** Always create a physical backup (`[artifact].md.bak`) before modifying an artifact. Shell commands must properly quote paths (e.g., `cp "source" "dest"`). If the validation fails or circuit breaker trips, it MUST execute `mv "[artifact].md.bak" "[artifact].md"` and `rm -f "[artifact].md.sig"`.
- **Crash Recovery Instruction (EC-P12-001):** If the agent crashes or stops unexpectedly, it MUST check for hanging `.bak` files on resume and either commit or rollback before proceeding.

## Downstream Validation
Before any artifact sealed by this loop can be consumed by `/code` or subsequent phases, the receiving agent MUST verify the `.sig` file against the current content hash using the Watchmen MCP (e.g., via `call_mcp_tool(ServerName="watchmen-mcp", ToolName="verify_pipeline_gate", ...)`). Do NOT rely on LLM visually checking the signature.
