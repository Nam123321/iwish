# 🛡️ Project Drift Detector Skill (SSOT V6)

## Purpose
`project-drift-detector` is the official operational wrapper for manually triggering Zero-Trust drift detection in the V6 architecture. 
It replaces the legacy AST scanners with `pipeline-integrity-runner.py` and FalkorDB UCG to detect **Contract Collisions**, **Code vs Spec Drift (Semantic Diff)**, and **Invalid Evidence Signatures**.

## Trigger Command
Users trigger this skill via the slash command: **`/detect-drift [Epic-ID | Story-ID]`** (e.g., `/detect-drift 88` or `/detect-drift 85.01`).

## Execution Protocol

When a user requests drift detection for a target (Epic or Story), the Agent MUST execute the following deterministic scripts. DO NOT guess or read files manually.

### 1. If Target is a STORY (e.g., `85.01`)
Run the following Zero-Trust Gates sequentially:

**A. Collision Check (FalkorDB Contract Graph)**
```bash
python3 .agent/scripts/pipeline-integrity-runner.py --target <Story_ID> --type story --phase collision
```
*Checks if the Story claims conflict with other Epics in the global database.*

**B. Semantic Diff (Code vs Specification)**
```bash
python3 .agent/scripts/pipeline-integrity-runner.py --target <Story_ID> --type story --phase semantic-diff
```
*Checks if the actual Prisma schema and API routing code deviate from the `data-spec.md` of this Story.*

**C. UI Spec Compliance**
```bash
python3 .agent/scripts/pipeline-integrity-runner.py --target <Story_ID> --type story --phase ui-spec-compliance
```

### 2. If Target is an EPIC (e.g., `88`)
An Epic defines the global bounds. If the user asks to check drift on an Epic, you must:

**A. Verify Epic Layer Design (SSOT Boundaries)**
```bash
python3 .agent/scripts/pipeline-integrity-runner.py --target <Epic_ID> --type epic --phase layer-design
```
*This validates the `layer-epic-db.md`, `contract_claims.yaml`, and AST models of the Epic.*

**B. Verify Epic Prerequisite Compliance**
```bash
python3 .agent/scripts/pipeline-integrity-runner.py --target <Epic_ID> --type epic --phase prerequisite-check
```

### 3. Diagnose Invalid Signatures (HMAC Scan)
Since V6 enforces strict HMAC sealing, older stories often have invalid signatures. You can check task sync status:
```bash
python3 .agent/scripts/flow-task-synchronizer.py --story-dir "_iwish-output/3. Development/1. Epic & Story/VS-<stream>/Epic-<id>/Story-<id>"
```

## Reporting Guidelines
After running the scripts, the Agent MUST:
1. Aggregate the output (PASS, PROVEN_SAFE, or FAILED).
2. If `pipeline-integrity-runner.py` outputs `Invalid HMAC signature`, explicitly advise the user that the artifacts were generated by a legacy process and recommend re-running `/make-story` or deleting the stale `.sig` files to clear the block.
3. Present the final findings clearly to the user using Markdown. Do not hallucinate drift; rely strictly on the script exit codes and stdout.
